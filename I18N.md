# Vietnamese and English interface

The current Vite app uses `i18next` and `react-i18next`. Vietnamese is the default. Header, authentication, organizer and admin language controls share the same setting, stored as `app_lang` in local storage. Switching language updates `document.documentElement.lang` and keeps the current route and form state.

## Adding or changing interface copy

Use `useTranslation()` inside a React component and translate at render time:

```tsx
const { t } = useTranslation();
return <button>{t('Lưu thay đổi')}</button>;
```

Vietnamese sentences are the translation keys. Add the matching English value to `src/i18n/locales/public.en.json` or `management.en.json`. Dots and colons are literal text, because key and namespace separators are disabled. Use interpolation for values rather than constructing a new translation key for every count.

```tsx
t('Còn {{count}} vé', { count: availableTickets })
```

Preserve stable IDs, API enums and filter values. Translate their displayed labels. Keep user-entered values and original event/organizer names intact. Unknown content falls back to its source text; the interface language selector does not automatically translate database event descriptions.

Keep API data as data, and format dates and prices in components using `src/utils/formatters.ts` and the active locale. VND remains VND in both languages; this feature does not convert currencies.

## Verification

```sh
npm test
npm run build
npm run lint
```

The i18n tests cover switching an existing login screen, preserving input, persistent preference, fallback content and locale formatting. Management tests cover catalog keys, expanded terms and ticket validation. Manual verification should include both language directions, reload, mobile/desktop and light/dark themes.
